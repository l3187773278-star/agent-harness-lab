## 2. 实验设计（为什么这个数字可信）

- **留出判分**：判分器是独立测试文件（`__grader__.test.js`），Agent 全程看不到；判分结果由 `node --test` 得出，不存在模型互评。见 ADR-0005。
- **单发基线不故意做弱**：基线把任务描述与相关文件**全文**一次性喂给模型、直接产出补丁，信息量不少于 Agent 第一步所获。见 ADR-0006。
- **双向验证防刷分**：每个任务的种子缺陷实现必须被评分器抓住、参考解法必须通过，`node bench/reference-solutions.mjs` 在 CI 强制执行。
- **Agent 一侧的难度来源**：多步试探、工具调用、执行反馈与自我纠错全部由运行时提供；基线的同信息量对照，隔离出「结构化运行时本身」的贡献。

## 5. 评测逼出的缺陷与修复闭环

每个缺陷都有「症状 → 根因 → 修复 → 回归验证」的完整证据链，修复均有对应测试或提交。

1. **SSE 流截断**：流被截断（尾部无换行的半截 JSON）时，旧实现把残缺数据当完整事件消费，导致工具调用参数错乱。修复：残缺数据直接丢弃并标记 `truncated`，供上层判为响应不完整。测试：`test/sse.test.js`（截断标记、半截 JSON 判 invalid）。
2. **stats 计数错误**：参数非法的工具调用曾中断整个循环且 invalidCalls 不计数。修复：非法调用被隔离、循环继续、计数准确。测试：`test/loop.test.js`。
3. **按字符切行**：token 估算与输出截断曾按「行」切分，超长单行直接把窗口撑爆。修复：改为按字符长度切分且内容无损（`splitString`）。测试：`test/recorder.test.js`。见 ADR-0003。
4. **批内重复调用误判**：同一批响应里的重复调用被误判为「无限重试」而打断。修复：重复检测按调用语义判定，达到上限才打断。测试：`test/loop.test.js`（重复达到上限主动打断）。
5. **t1 判分契约缺陷**：flash 首跑中 t1 的 Agent 与基线**双双失败**，双向验证定位到评分器契约与种子实现不匹配（种子本身违反「省略号长度不超过上限」契约，属于无效种子）。修复评分契约与种子后，v4-pro 单任务复跑 1/1。教训：判分契约必须对种子与参考解法同样生效，否则评测的是契约 bug 而不是 Agent 能力。
6. **请求超时预算与 reasoning_effort 不匹配**：主运行前身（10-27-26）在 t5 连续触发 120s 请求超时——v4-pro 的 effort=max 档在十万级 token 上下文上，单次响应超过默认 120s 预算。修复：新增 `--timeout` CLI 选项（提交 `90c944b`），正式运行以 900s 预算执行。
7. **无效工具调用未回填 tool 响应（API 400）**：主运行 t6 第 5 步出现一个坏 JSON 参数的工具调用，运行时把它排除在 assistant 消息的 tool_calls 之外，却仍回灌了它的错误 tool 响应——孤儿 tool 消息直接触发 OpenAI 兼容协议的 400（`tool_call_id did not have response messages`）。修复：assistant 消息包含**全部**调用（无效调用用原始 argsText 回显、缺失 id 用 `invalid_${index}` 兜底），错误回灌使用同一 id（提交 `325a07b`）；新增协议回归测试（`test/loop.test.js`，断言每个 tool_call 都有对应 tool 响应）。修复后 t6 复跑 1/1。

8. **判分未固定时区（CI 抓出）**：t6 的任务语义与时区强相关——种子缺陷（用 UTC 取日期）只在非 UTC 时区下显现。判分进程原先跟随宿主机时区，在本机（Asia/Shanghai）能抓到种子，在 CI runner（UTC）却抓不到，冒烟测试报「评测器接线有误」。修复：`bench/runner.js` 与 `bench/reference-solutions.mjs` 在拉起判分进程时固定 `TZ=Asia/Shanghai`，判分结果与本机一致。教训：与时间/时区相关的判分必须显式固定环境，不能依赖宿主机默认值。

另有 ADR-0007 记录的信号量许可交接模型（t4 任务建设期间三种错误种子写法的辨析，最终以 `inUse` 为唯一权威计数）。
