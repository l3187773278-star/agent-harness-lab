# ADR-0001：为什么零运行时依赖

- 状态：已接受
- 日期：2026-10-03

## 背景

这个项目要调用大模型 API、解析 SSE、执行工具、跑评测。主流做法是引入
`openai` SDK、`yaml`、`dotenv`、测试框架等一堆依赖，快速拼起来。

## 决策

`package.json` 的 `dependencies` 必须为空对象。只用 Node.js 内置模块
（`fetch`、`node:test`、`node:fs` 等），并在 CI 里加"零依赖断言"防止回退。

## 理由

1. **可验证性**：面试官 clone 下来 `node src/cli.js selftest` 就能跑，
   不用先装一堆包。对"简历上的项目"来说，这一步的摩擦越小，可信度越高。
2. **每一行都可解释**：用 SDK 等于把协议层外包了。手写 SSE 解析逼出了真实的
   边界问题（分片跨界、并行工具调用交错、截断流），这些问题才是这个项目的价值。
3. **可复现性**：评测结果不该依赖某个依赖库的某个版本行为。零依赖让
   "同一份代码在不同机器上跑出同样结果"变得简单。

## 代价与换取

- 代价：要自己实现 SSE 解析、`.env` 解析、YAML 一行式读取、token 估算。
- 换取：这些恰好是**本项目真正想展示的工程能力**。用依赖换掉的不是重复劳动，
  而是这个项目的核心资产。

## 例外

- `devDependencies` 里的 `eslint` / `prettier` 允许存在：它们只影响开发期，
  不影响运行时，也不参与评测。
