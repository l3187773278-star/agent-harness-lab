# ADR-0007：异步信号量的许可交接模型（评测集建设教训）

- 状态：已接受
- 日期：2026-10-03
- 背景：评测任务 t4-semaphore 建设过程

## 问题

为任务 t4 设计"有并发缺陷的信号量"时，尝试了三种错误写法，前两种都无法被
行为测试稳定抓住：

1. **"release 不归还许可"**：在 Promise.all 风格的负载下，先来后到的唤醒链
   恰好把账目误差抵消了，行为上几乎不可观测。
2. **"等待者被唤醒后重新扣减 available"**：与 release 的归还发生重复递减，
   `available` 被减成负数，导致**所有后续 acquire 永久阻塞**（死锁）——
   这不是"有缺陷但能跑"，是直接挂死，不适合做评测种子。

## 结论：正确的账目模型

`inUse` 作为**唯一权威**计数（`available = limit - inUse` 派生），
许可在 `release()` 时就完成转移：

- 有等待者：把许可转交给队首（`inUse` 不变：释放者 -1、等待者 +1 抵消），
  只唤醒**一个**。
- 无等待者：`inUse -= 1`。

等待者被唤醒后**不做任何记账** —— 账已经在 release 时记完了。

## 最终选用的种子缺陷

"一次唤醒所有等待者"（notifyAll 式的错误）：一份许可唤醒了整个队列，
所有等待者都以为自己拿到了许可，实际并发数远超 limit。这个缺陷
**确定性地**被"并发峰值"类测试抓住，且修法清晰（只唤醒队首一个）。

## 对这个项目的意义

1. 证明了"种子缺陷必须可被行为测试确定性抓住"这条任务建设标准。
2. 这份教训直接写进了任务 t4 的 prompt 提示与参考解法注释里。
3. 它是 `docs/report.md` 之外，最能体现"评测集本身经过工程验证"的证据。
