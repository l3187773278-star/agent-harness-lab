# ADR-0006：单发基线为什么给全文

- 状态：已接受
- 日期：2026-10-03

## 背景

本项目的核心命题是"结构化的 Agent 运行时比直接问模型强多少"。要证明
这一点，对照组（基线）必须公平 —— 把基线做弱来制造好看数字，面试官一问就穿。

## 决策

单发基线拿到**工作区全部文件的完整内容**（与 Agent 第一步能读到的信息量一致），
一次调用直接产出"文件 → 修复后完整内容"的 JSON 补丁，应用到干净的工作区后
用同一套评分器判分。

## 为什么这样算公平

| 维度 | Agent | 单发基线 |
| --- | --- | --- |
| 信息量 | 按需读文件 | 一次性拿到全部文件 |
| 行动能力 | 多步工具调用 | 只能一次输出 |
| 反馈机会 | 跑测试、看结果、纠错 | 无 |
| 判分 | 同一套留出测试 | 同一套留出测试 |

基线在**信息**上不吃亏（甚至更占便宜），吃亏的是**行动与反馈**。
这正是要对比的差异：多步试探、执行验证、自我纠错到底值多少。

## 补充说明

- 基线不禁止它"在脑子里模拟"测试 —— 它拿不到判分器，但拿得到可见测试文件，
  和 Agent 一样。
- 基线输出的 JSON 解析失败也记为失败，并且把原文片段存进报告，防止"解析器
  把模型冤枉了"。
- 若基线也通过了，说明该任务本身不需要多步 —— 这类任务对 Agent 的区分度低，
  报告里会单独标注。
